# 计划：任务卡定时自动化执行（2026-11）

## 背景

看板最初只能手动「开始执行」：卡片派发到一个会话里跑一轮，结果回收到「待验收」。用户希望**新建任务时就能创建自动化任务**，也就是一张卡按计划自己重复执行，不用每次手动点。

## 目标

- 新建任务面板里能选「定时执行」，支持每小时 / 每天 / 每周（多选星期几）；也支持自定义 RRULE。
- 到点自动把卡片派发执行，进度与结果沿用现有链路（进行中 → 待验收）。
- 卡片与详情里能看规则、下次执行时间，能暂停 / 启用 / 改规则 / 取消自动化；删卡级联删除定时任务。
- 会话里的 agent 也能通过 `task_board` 的 `automation` 参数创建/修改自动化卡。

## 方案选择

| 方案 | 结论 |
|---|---|
| 插件自己起定时器轮询 `board.json` | 简单，但 Harness 没运行时不会投递，规则也不进 DSH 的「自动化任务」页面 |
| 复用 DSH 内置 `schedule` 服务 | **采用**。规则持久化、重启后补投、UI 可见、投递由宿主负责 |

## 关键设计

1. **规则**：界面给「频率 / 时间 / 星期几」，Host 编成 RRULE 字符串（`DTSTART;TZID=<IANA 时区>:20260101THHMM00` + `RRULE:FREQ=DAILY|WEEKLY;BYDAY=…|HOURLY`），锚点日期固定、只借它的时钟时间。
2. **投递目标用 `new_once`**：创建定时任务时宿主会预留一个会话 id，同一个卡片的每次执行都在这个会话里，避免每轮新建会话把侧栏塞满。
3. **会话接管**：看板监听 `session/event`，来自预留会话的 `turn/start` 才把会话写进卡片、切「进行中」并记 `lastFiredAt`；上一轮结束后的新 `turn/start` 视为新一轮，进度重置。
4. **状态查询**：`schedule.catalog()` 带 1.5s 缓存，`schedule/changed` 失效；用 `schedulesRevision` 让客户端只在「下次执行/状态」变化时重渲染。
5. **工作目录**：自动化会话优先落在发起操作的会话所在目录，其次取第一个工作区，最后退回部署默认目录。
6. **立即执行**：自动化卡的「开始执行」走 `schedule.run`（投递一次，不移动计划中的下一次），普通卡仍走会话派发。

## 改动清单

| 文件 | 改动 |
|---|---|
| `src/board.js` | 卡片 `automation` 字段与归一化、`setAutomation`、`bindAutomationRun`、事件接管逻辑 |
| `src/host.js` | RRULE 生成、定时任务增删改查、`/state` 附带运行时状态、`task_board` 工具 `automation` 参数 |
| `client/app.jsx` | 新建面板的自动化区块、规则编辑器（频率/时间/星期）、卡片徽标、详情自动化区块 |
| `client/i18n.js` | 中英文案 |
| `client/store.js` | `schedulesRevision` 参与刷新判断 |
| `client/styles.css` | 自动化相关样式 |
| `README.md` / `docs/` | 功能说明与文档 |

## 验证

- 单元级：RRULE 生成（daily / weekly / hourly / 非法时区回退）、看板事件接管与进度重置。
- 端到端（本机 profile，链接本地目录）：建卡即建定时任务（`new_once` 预留会话、cwd 正确）→ 暂停 / 改规则 / 恢复 → 「立即执行」真实投递 → 卡片自动接上会话、进度到 100%、结果写入 → 删卡后定时任务同步消失。
- 界面：仅构建与槽位注册校验，未做截图验证（环境无浏览器控制）。

## 遗留

- 自动化卡的会话若被用户归档，投递会失败并在卡片上报错，需要重新设置规则。
- 卡片进入「已完成」后，下一轮仍会重新开始；如不希望继续，需要暂停或取消自动化。
- 计划中的后续：GitHub Actions tag 发布流水线；UI 视觉验证。
