# 卡片上下拖动排序

## 背景

看板卡片一直可以拖到别的列换状态，但同一列里无法调整上下顺序。空间一键排队按「待办从上到下」
执行，用户却没有任何办法控制这个顺序，只能按创建先后跑。

目标：

- 同一列里把卡片拖到另一张卡的上半/下半，插入到它前面/后面；
- 拖到列尾空白处，排到该列最后；
- 拖到别的列仍按原逻辑换列（不改变现有拖拽换列行为）；
- 顺序变化持久化到 `board.json`，刷新、重载插件、队列执行都按新顺序。

范围只做鼠标拖拽排序，不做触屏长按排序、不做键盘排序。

## 数据模型

不新增字段，也不升文件版本：

- 面板按 `Board.tasks` 数组顺序渲染，数组顺序就是真实的展示顺序；
- 排序时把卡片从数组里取出，插到目标卡前面/后面（或数组末尾），再把所有卡片的 `order`
  重新编号成 `1..n`，保证 `order` 与数组顺序一致、下次 `add` 仍追加到末尾；
- 卡片顺序和空间队列共用同一份顺序：`startQueue` 拍快照时就是当前数组里的待办顺序。

## Host（src/board.js、src/host.js）

- `Board.reorder(id, targetId, position)`：
  - `targetId` 为空 → 移到该列末尾；
  - 目标卡与当前卡不在同一列 → 拒绝（跨列仍由 `move` 处理）；
  - 拖到自己身上 → 空操作；
  - 成功后重新编号 `order`、`touch()` 落盘。
- `POST /task-board/op` 新增 `reorder { id, targetId, position: 'before' | 'after' }`，
  返回 `{ ok, task, state }`。
- 队列、自动化和工具接口都不变；`reorder` 只改顺序，不触发换列的自动化暂停/恢复逻辑。

## 面板（client/）

- `Card` 在拖拽经过时判断指针在卡片上半还是下半，显示一条插入线（`is-drop-before` /
  `is-drop-after`），松手调用 `reorder`；
- 只有同列目标才在卡片上拦截拖拽；目标是别的列时不拦截，事件继续冒泡到整列，仍走
  `move` 换列；
- 拖拽来源卡 id 存在快照的 `dragging` 字段，`dragend` 时清空，顺带清掉所有残留的插入提示；
- 列尾空白处：如果被拖的卡本来就在这一列，排到末尾；否则换列；
- 已完成的两行小卡同样支持上下排序；
- 无新增文案，纯交互变化。

## 兼容性

- 不动 `board.json` 结构，旧文件与旧客户端都不受影响；
- 旧卡片的 `order` 可能不连续，第一次排序后会重新编号；不排序时现有展示顺序不变；
- 跨列拖拽行为与之前一致。

## 验证

- `npm test`：27 个用例全部通过，其中新增 `test/board-reorder.test.mjs`：
  - 同列前/后插入、移到列尾、`order` 重新编号；
  - 跨列拒绝、拖到自己身上空操作；
  - 重新排序后空间队列按新顺序拍快照；
  - 排序落盘后重新加载顺序保持。
- `npm run smoke` 通过：`scripts/dev/smoke-queue.mjs` 在建卡后先调用 `reorder` 把
  `third → first → second`，再启动队列，确认派发顺序与调整后的顺序一致；既有 Codex /
  自动化冒烟无回归。
- `node scripts/build.mjs` 产出 `dist/client.js` 100.5 KB。
- 未在真实 GUI 里实际拖拽验证：客户端改动刷新页面生效，Host 的 `reorder` 接口需要按
  [deploy.md](../deploy.md) 重新加载 bundle 后生效。
